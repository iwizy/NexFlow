## Scope

This milestone reviews predictable repository validation, diagnostics,
inventory, and scoped support statements. It includes the cumulative repository
snapshot, including experimental profiles and later-milestone preparation;
their presence does not complete those later milestones.

The [0.1 frozen scope](../docs/0.1-scope.md) remains historical. This successor
review includes optional credential policy, the compact Solo Developer
example, additional offline extension schemas and fixtures, and disposable
repository tooling without silently rewriting the `v0.1.0` scope.

## Compatibility And Migration

- Manifest `specVersion` stays `"0.1"`; unsupported manifest versions remain
  unsupported. Seventeen core manifest kinds are unchanged.
- Core schema changes since `v0.1.0` add optional Project credential policy and
  common definitions. They do not add a required top-level field. The older
  snapshot does not validate or implement the new policy contract; consumers
  must pin the intended revision rather than assume equivalence from `0.1`.
- Minimal Team is now a three-manifest Core Profile path. Solo Developer adds
  ten manifests; six complete examples retain sixteen each. The resulting
  109-manifest count is an intentional onboarding change, not lost kind coverage.
- Maintained active-definition selection is exercised by focused checks, not
  an active definition in the compact examples.
- Existing legacy actor/agent, provider, approval-target, and discovery forms
  retain their documented migration treatment. No form is removed by this review.
- CLI `formatVersion: "0.4-draft"`, claim/readiness formats, and extension
  profiles keep their independent versions. The repository prototype remains
  unreleased; no installable package or public executable is introduced.
- The maintenance lockfile uses `fast-uri@3.1.8`; the prior vulnerable
  `3.1.3` resolution is not reused. No manifest migration follows from this fix.

## Release Notes

NexFlow `v0.2.0` is the validation and conformance milestone after `v0.1.0`.
It provides one pinned snapshot of the draft specification, structural schemas,
maintained examples, and reproducible repository checks.

Highlights include unified validation, cataloged positive and negative
fixtures, explicit inventory and Core Profile boundaries, evidence-scoped
conformance vocabulary, diagnostic regression checks, adopter and migration
guidance, and the corrected maintenance dependency.

Experimental repository `validate`, `inspect`, `graph`, and bounded `init`
commands remain source-checkout prototypes, not a released reference CLI.
Integration profiles are offline declarations, not live clients. There is no
runtime, provider calling, automatic approval enforcement, orchestration,
deployment, or complete semantic validator. Draft RFCs remain Draft.

Manifest `specVersion` remains `"0.1"`. The next release line is `0.3` semantic
consistency; runtime decision readiness remains a separate `0.4` gate.
