## Manual Contract Scenarios For Review

These are maintainer-reviewed expectations already described by the owning
documents, not executed tests or new accepted semantics. Approval confirms this
bounded specification treatment, not runtime enforcement or RFC acceptance.

- Memory read by an actor outside `allowedConsumers`: reject under the future
  runtime model; a resolved actor reference alone is not authorization.
- Plain-language visibility broader than the explicit consumer list: use the
  narrower interpretation; do not infer additional consumers.
- Task-to-project promotion without declared policy or required approval:
  require explicit policy/approval, not automatic durable retention.
- Confidential source summarized into internal memory: preserve the stricter
  classification or split scopes; summarization does not remove sensitivity.
- Expired retained data: follow the owner's retention/deletion rule. Current
  tooling does not parse a deadline, delete data, or prove expiry enforcement.
- Approval target resolved but approval expired, revoked, or out of scope:
  target existence cannot make an action approved.
- Provider with `trainingUse: unspecified` where the model requires prohibited
  training: unresolved restrictive fact is a blocker, not satisfied eligibility.
- Fallback to another provider: return to host selection and reevaluate all
  applicable policies and approvals; an adapter cannot silently substitute it.
- Valid EventSet declaration: proves neither that an event instance happened
  nor that it was persisted, redacted, authorized, or delivered.
- Resolved Agent Assembly projection: unresolved runtime facts remain visible;
  a read-only derived view is not an execution grant.

## Proposed Release Notes

NexFlow `v0.3.0` is the semantic-consistency milestone following `v0.2.0`.
It reviews the cumulative cross-manifest model: exact reference namespaces,
work step/artifact identity, human-controlled approval and override boundaries,
memory ownership and visibility, event declarations, provider constraints and
fallback expectations, active-definition authority, and Agent Assembly
provenance and blockers.

Structural and selected semantic checks accompany the specification. The
semantic inventory records coverage and gaps rather than presenting schema
success as complete semantic conformance. Memory policy, provider selection,
live approval, effective assembly, and runtime enforcement remain specified or
partial, not executable guarantees. Draft RFCs are not promoted by the tag.

Manifest `specVersion` stays `"0.1"`; independently versioned profiles, claim
records, and experimental CLI output do not advance automatically. This
milestone does not distribute a reference CLI, runtime, provider adapter,
schema bundle, live integration, or orchestration engine.

The next line is `0.4` runtime decision readiness. Its comparative prototypes,
hard-gate results, target measurements, packaging/security evidence, ownership,
and architecture review are still incomplete. `0.5` remains blocked behind it.
