## Proposed Publication And Trust Boundary

The proposed `v0.4.0` format is a repository specification/decision snapshot:
an eventual GitHub release with notes, exact-commit evidence and checksums,
plus GitHub's source archives. It is **not** an npm/PyPI/crates/module package,
binary, installer, app, bundled Node runtime or runnable evaluation-capsule
asset. Source archives still contain experimental source code and locks; the
fresh advisory findings remain visible and are not excused by this format.

The public repository is `iwizy/NexFlow`, default branch `main`, with the
maintainer account's repository administration recorded by read-only API
inspection. Current published milestones are v0.1.0, v0.2.0 and v0.3.0; no
v0.4 tag or release exists in the captured release list. A later authorized
publication must verify the remote tag resolves to the exact final candidate,
download every offered asset/source archive, and verify asset checksums and
the archive's expected tree. A SHA-256 checksum detects byte changes relative
to its trusted copy; it is not an independent publisher signature. GitHub
account/HTTPS delivery is the stated transport trust, not proof of private
account security, OS certification or an independently signed publisher.

Project Developer ID/notarization and Windows signing are **not applicable to
this proposed non-executable release asset format**, and remain **not performed**.
No certificate exists or is borrowed. Native app/installer/standalone or bundled
runtime publication reopens the applicable publisher, runtime verification,
signing and platform lifecycle gates. No OS bypass or keychain change is needed.
Runtime provisioning and trust remain the consumer's separate prerequisite when
using experimental sources; this release review makes no new runtime support
promise. License inventories and two missing upstream build-tool notices remain
limitations; no legal approval or redistribution of those tool archives is offered.
