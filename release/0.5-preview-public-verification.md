# Verify the public first alpha

Use **Reference Public Release Verification** in GitHub Actions after the
authorized `v0.5.0-alpha.1` prerelease is public. The workflow must be available
on the default branch before it can be dispatched. Use the approved release
receipt inputs:

| Input | Source |
| --- | --- |
| `release_sha` | The full approved commit for the tag. |
| `checksums_sha256` | The SHA-256 of the reviewed packet's `SHA256SUMS` file. |
| `node_version` | The exact Node.js version from the reviewed `PROVENANCE.json`. |

Record the checksum input from the approved packet before upload. Use the
runtime and checksums of the final candidate if qualification changes after
the security bulletin.

The run checks Linux AMD64 on `ubuntu-24.04`, macOS ARM64 on `macos-15`, and
Windows AMD64 on `windows-2025`. Each job checks the published prerelease and
its tag commit, downloads the 14 named assets without authentication, then
verifies the API digests, downloaded bytes and inventory against the approved
checksum input. Both packages are installed offline from those downloads in
separate consumers with empty caches. The jobs exercise the documented quick
start through the installed command, a duplicate-key rejection, the pure
validation import and scoped uninstall.

Retain the three job artifacts. Each contains verified downloads and a
`receipt.json` with the release and asset IDs, hashes, environment, command
results and any failure. Record these artifacts and all three outcomes in the
[publication receipt](0.5-preview-publication.md#public-download-and-install-receipt).
This run covers public bytes and the developer installation route. Publisher
trust and the broader native lifecycle evidence are tracked separately.
